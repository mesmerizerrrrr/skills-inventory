# 테이블 생성 규칙
- 모든 테이블은 prefix 로 "tbl_" 로 시작합니다. ex) tbl_user, tbl_user_info, ...
- 위 사항 외에는 테이블명에 대한 규칙은 엄격하지 않으며, 너무 긴 테이블명이 아니라면 약어가 아닌 일반적인 단어를 사용하여 구성해도 됩니다.
- 모든 테이블은 기본적으로 관리용도로 아래 2개 컬럼이 필요합니다.
  - reger_id :
    - 물리명 : reger_id
    - 논리명 : 등록자 아이디
    - 자료형 : varchar(50)
    - not null 컬럼이며, default 값으로 'SYSTEM' 을 사용합니다.
    - ex) `reger_id varchar(50) not null default 'SYSTEM'`
  - reg_dtm :
    - 물리명 : reg_dtm
    - 논리명 : 등록 일시
    - 자료형 : timestamp(6)
    - not null 컬럼이며, default 값으로 now() 를 사용합니다.
    - ex) `reg_dtm timestamp(6) not null default now()`
    - 해당 컬럼은 DBA 의 운영 관리 용도를 위해서 필수 인덱스로 활용되어야하는 컬럼이기도 합니다. (모든 테이블 생성 ddl 에 기본적으로 인덱스로 추가합니다.)
      - `create index idx_${테이블}_reg_dtm on ${스키마}.${테이블}(reg_dtm);`
- 외래키 관련 : 기본적으로 모든 테이블간의 관계는 설계상 (논리적) 으로만 존재하며, 물리적으로 fk 연결등을 해놓지 않습니다.
  - 하지만, 운영 관리등을 실질적으로는 외래키 였어야하는 컬럼에는 주석에 반드시 관련 내용을 적어둡니다.
  - ex) user_id 라는 컬럼이 실제로는 다른 테이블의 pk 인 경우 , 주석 = `사용자 아이디 (etoostbl.tbl_user.user_id)`

# 인덱스 생성 규칙
- 인덱스 명칭 규칙 :
  - 단일 인덱스 : `idx_${테이블명}_${컬럼명}`
  - 2개 이상의 복합 인덱스 : `idx_${테이블명}_${선두_컬럼명}`
  - 만약 인덱스 선두컬럼이 동일한 복합 인덱스가 있다면 뒤에 _${순서} 를 붙여줍니다. ex) idx_${테이블명}_reg_dtm_1, idx_${테이블명}_reg_dtm_2
