# 코드 매핑 적용 판단

숫자·문자 코드의 성격이나 Converter의 공통 적용 범위가 불명확할 때만 읽는다.

## 적용 판단

다음은 판단 방법을 보여주는 가상 저장 계약이다. 예시의 코드값을 다른 도메인에 그대로 적용하지 않는다.

| 저장 계약 예시 | 판단 |
| --- | --- |
| 수강 상태를 DB 문자열 `"1"`로 저장하고 Java에서는 `ENROLLED`로 표현함 | 의미명과 저장 코드가 다르므로 코드 값을 가진 enum과 Converter 사용 |
| 단일 선택형 문항을 DB `"S"`로 저장하고 Java에서는 `RADIO_BTN`로 표현함 | 같은 방식으로 의미와 저장값 분리 |
| 랜딩 동작을 DB `"POPUP"`로 저장하고 Java enum명도 `POPUP`임 | 기존 `@Enumerated(EnumType.STRING)` 유지 |
| 기존 `ORDINAL`의 선언 순서와 DB 저장 계약이 명시적으로 일치함 | 이 스킬을 이유로 Converter로 전환하지 않고 기존 매핑 유지 |
| 컬럼이 숫자이지만 의미·자료형만 알려져 있고 코드표는 없음 | Converter 적용 여부를 아직 결정하지 않음. 실제 코드와 의미를 확인 |
| 여러 대상 유형을 하나의 숫자 비트마스크에 저장함 | 단일 enum 코드 매핑으로 다루지 않고 기존 비트마스크 모델 유지 |

날짜 문자열이나 특수 boolean 변환은 이 스킬의 업무 코드 enum 적용 범위에 포함하지 않는다.

## 공통화할 때 확인할 경계

- 프로젝트에 `PersistableCodeEnum#getDbValue()`로 명시된 DB 값을 읽는 공통 Converter가 있다면 재사용한다. enum명이나 ordinal로 저장 코드를 대신하지 않는다.
- 미정의 값에서 null을 반환하는 구현과 예외를 던지는 구현은 서로 다른 계약이다. 대상 Converter의 실제 처리를 확인하고 다른 타입에도 같은 정책이 적용된다고 단정하지 않는다.
- DB 요일 코드는 Java 요일 값과 의미나 시작점이 다를 수 있다. 코드표를 확인하고 해당 요일 체계나 `autoApply` 설정을 다른 컬럼에 복제하지 않는다.
- 여러 유형을 함께 저장하는 비트마스크는 단일 업무 코드와 구분한다. 현재 저장 계약이 비트마스크라면 단일 enum용 Converter를 도입하지 않는다.
- 소스에서 확인한 코드표와 운영 DB의 저장값 검증은 구분한다. 코드의 읽기·쓰기 왕복을 확인해도 운영 데이터 전체를 검증한 것은 아니다.
