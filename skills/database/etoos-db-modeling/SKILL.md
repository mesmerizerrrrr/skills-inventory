# 이투스 DB 모델링·설계

업무 요구사항을 테이블·컬럼·관계로 설계하고 DBA가 검토할 수 있는 `.sql` 파일로 전달한다. 이투스 기준을 적용하는 작업에 사용하며, 다른 조직의 모델링 규칙을 임의로 대체하지 않는다.

## 공통 기준과 의존 스킬

먼저 [이투스 공통 기준](../etoos-postgresql-ddl/references/standards.md)을 읽는다. 용어사전·내부 모델링 가이드·예제는 `etoos-postgresql-ddl` 스킬에서 함께 관리한다.

설계 결과의 SQL 작성에는 [etoos-postgresql-ddl](../etoos-postgresql-ddl/SKILL.md)을 함께 적용한다. 이 스킬을 옮기거나 설치할 때 두 스킬을 함께 제공한다. 의존 파일이 없으면 그 사실을 알리고 이투스 기준 준수를 확인했다고 표현하지 않는다.

## 설계 절차

1. **업무와 현재 구조 파악**
   - 저장할 업무 대상, 한 행의 의미, 생성·변경·종료 시점, 주요 조회·등록·수정 방식부터 확인한다.
   - 신규 설계인지 기존 테이블 변경인지 구분하고, 제공된 현재 DDL·소스·요구사항에서 기존 관계와 데이터 의미를 읽는다.
   - 대상 스키마·PostgreSQL 버전·데이터 규모는 제공된 근거를 사용한다. 예제의 스키마명, 적재량, 배치 방식은 기본값이 아니다.
2. **테이블·키·관계 결정**
   - 한 행의 식별 기준과 중복 허용 범위를 정하고 단일키·복합키·자동증가 여부를 업무에 맞게 선택한다. 모든 테이블에 임의의 identity PK를 추가하지 않는다.
   - 관계의 방향·카디널리티·선택 여부를 정의한다. 관계 컬럼의 자료형은 참조 키와 호환되게 하고 실제 참조 대상은 컬럼 주석에 남긴다.
   - 이투스 기본 규칙은 논리 관계이며 물리 FK를 만들지 않는다. 이때 관련 데이터의 삭제·변경과 정합성을 어느 처리에서 관리할지 설계상 확인한다.
3. **컬럼명과 의미 결정**
   - [용어 조회 방법](../etoos-postgresql-ddl/SKILL.md#용어사전-조회)에 따라 정확한 논리명·물리명을 검색한다. 전체 사전을 미리 읽지 않는다.
   - 같은 논리명의 후보가 여럿이면 설명과 해당 업무의 기존 용례로 판단한다. 의미가 같다고 확인되지 않은 약어를 임의로 선택하지 않는다.
   - 사전의 단어를 조합할 수 있으나 각 구성 단어의 근거를 확인한다. 기존 복합 용어의 의미도 확인하며, 신규 단어 등록이 필요하면 후보와 이유를 준비한 뒤 사용자에게 확인한다. 이미 승인된 동일 용어는 재확인하지 않는다.
4. **자료형·NULL·기본값 결정**
   - 공통 기준의 허용 자료형과 실제 값의 범위·길이를 함께 사용한다. 용어사전은 자료형 사전이 아니다.
   - `not null`을 우선 검토하되 미입력·조건부 사용 등 의미 있는 NULL을 허용할 수 있다. NULL을 피하려고 임의의 빈 문자열·0·날짜를 만들지 않는다.
   - 여부·상수값·조건부 컬럼은 허용값과 사용 조건을 주석으로 설명한다. 여부의 기본값은 업무 의미로 정한다.
   - 새 테이블의 필수 관리 컬럼 2개와 등록 일시 인덱스를 포함한다. 수정자·수정 일시 등 추가 관리 컬럼은 실제 요구에 따라 결정한다.
5. **업무 인덱스 결정**
   - 실제 조회 조건·정렬·조인·중복 방지 요구를 근거로 컬럼과 순서를 정한다. 이름만 보고 모든 컬럼에 인덱스를 만들지 않는다.
   - 업무 인덱스마다 용도 주석을 남긴다. unique 인덱스는 NULL을 포함한 중복의 의미도 확인한다.
6. **SQL로 전달하고 검토**
   - `etoos-postgresql-ddl`의 절차로 `.sql` 파일을 작성한다. 업무 전제·논리 관계·설계 이유는 필요한 만큼 SQL 주석에 담는다.
   - 설계 검토 요청이면 지적할 문제와 수정안을 요청 범위에 맞게 제공한다. 사용자가 설명만 요청했다면 파일 생성을 강제하지 않는다.

## 미확정 사항과 완료 기준

- 스키마·키·용어 등 실행 가능한 DDL을 좌우하는 정보가 없으면 해당 부분을 질문한다. 답변 전에도 확정된 설계를 진행하고 결과를 검토용 초안으로 표시한다.
- 신규 용어 등록 확인은 [내부 모델링 가이드의 컬럼 생성 규칙](../etoos-postgresql-ddl/references/internal-modeling-guide.md#컬럼-생성-규칙)에 따른다. 확인을 요청할 때 해당 규칙과 필요한 후보를 함께 설명한다.
- 결과에는 테이블별 한 행의 의미, 키·중복 기준, 컬럼명 근거, 논리 참조, NULL 예외, 업무 인덱스의 용도가 드러나야 한다. 별도 문서를 일률적으로 추가할 필요는 없다.
- 내부 모델링 기준과 다른 설계는 사용자 요청 또는 확인된 프로젝트 규약에 따른 예외인지 표시한다. 현재 요청이 해당 기준과 충돌하면 현재 요청을 우선한다.
- `.sql` 경로와 검토 범위, 남은 미확정 사항을 알린다. 설계·정적 점검과 실제 DB 실행 검증을 구분한다.
