# 검증과 오류 처리 선택

검증 위치, 상세 메시지 전달, 기존 예외 재사용 여부를 판단할 때 사용한다. 아래 타입 이름과 숫자는 예시이며 실제 공통 타입·제약·HTTP 상태는 대상 프로젝트의 계약을 따른다.

## 필드와 복합 검증

```java
@NotBlank(message = "일정 이름을 입력해 주세요.")
@Size(max = 100, message = "일정 이름은 100자 이하여야 합니다.")
@Schema(description = "일정 이름", maxLength = 100)
private String name;
```

위와 같이 런타임 제약과 문서의 길이 설명을 맞춘다. `100`을 공통 제한값으로 채택하지 말고 실제 API의 허용 길이를 사용한다. Swagger를 사용하지 않는 프로젝트에 이 예시만을 이유로 문서 도구를 추가하지 않는다.

필드끼리의 조건이 필요하면 요청 DTO의 검증 메서드에서 비교한다. 다음은 시작·종료 시각의 필수 검증을 각 필드의 `@NotNull`이 담당하는 경우의 메서드 예시다.

```java
@Hidden
@AssertTrue(message = "종료 시각은 시작 시각보다 이후여야 합니다.")
public boolean isPeriodValid() {
    if (startAt == null || endAt == null) {
        return true;
    }
    return endAt.isAfter(startAt);
}
```

누락값을 여기에서 통과시키는 이유는 필드의 필수 검증에 맡기고 비교 중 NPE를 피하기 위해서다. 실제 입력이 선택값이면 누락 시 의미에 맞게 조건을 바꾼다. `@Hidden`은 Swagger 노출만 제어하며 검증을 실행하지 않는다. App/Internal 양쪽에서 같은 요청을 받는다면 각 진입점의 `@Valid` 등 검증 연결을 확인한다.

## 업무 실패와 응답 연결

| 상황 | 선택과 이유 |
| --- | --- |
| DB 조회 결과나 사용자 권한·상태로 판단해야 함 | 기존 Service 등 업무 판단 위치에서 검사한다. DTO에 Repository를 주입하지 않는다. |
| 클라이언트가 예약 중복 등 실패 종류를 구분해야 함 | 의미가 같은 도메인 예외·공통 응답 코드를 재사용한다. 없으면 해당 실패를 기존 공통 예외 계층에 연결한다. |
| 같은 업무 코드 안에서 상세 이유만 달라짐 | 공통 예외의 상세 메시지 생성자를 사용하고 공통 처리기가 그 값을 응답에 반영하는지 확인한다. 조건마다 새 코드·예외 타입을 만들지 않는다. |
| 조회 대상이 없음 | 기존 도메인 또는 공통 `NotFoundException` 체계를 사용한다. 중복 오류 계층을 추가하지 않는다. |
| 파일의 형식·크기·확장자를 검사함 | 기존 공통 제약 어노테이션과 validator를 재사용한다. 여러 조건을 나누면 필요한 검증을 조합할 수 있으며 허용 확장자·용량은 업무 설정을 따른다. |

도메인 예외가 `BaseException`과 `ResponseCode`에 연결되는 구조라면 예외 생성부터 공통 Advice의 메시지·HTTP 상태 변환까지 확인한다. 성공 응답도 공통 Advice가 감싸는 구조에서는 Controller가 실제 DTO·목록·`void`를 반환하고 응답을 중복 포장하지 않는다.

## 적용 경계

- 예외 패키지의 `exception`/`exceptions`와 클래스 접미사는 기존 도메인을 따른다. 규칙을 맞추기 위한 일괄 이름 변경은 하지 않는다.
- 업무 오류가 HTTP 422를 사용하더라도 모든 실패를 그 상태로 고정하지 않는다. 현재 응답 코드 배정과 API 계약이 기준이다.
- 일반 인자 오류는 기존 `InvalidArgumentException`과 상세 메시지로 표현할 수 있다. 라이브러리 오류·DB 변환 오류·내부 장애까지 무조건 클라이언트 요청 오류로 치환하지 않는다.
- 요청 형식 오류의 원인 메시지를 그대로 응답에 노출하지 않는다. 사용자가 이해할 메시지와 내부 진단 정보를 구분하고 기존 공통 처리 방식을 따른다.
- 응답을 직접 내보내야 하는 특수 진입점은 적용 중인 Advice 범위와 현재 우회 수단을 확인한다. 특정 어노테이션 이름이나 임의의 우회 계층을 공통 방식으로 새로 도입하지 않는다.
