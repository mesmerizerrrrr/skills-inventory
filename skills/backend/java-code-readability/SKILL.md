# Java 구현 코드 가독성

## 목적과 범위

메서드를 읽을 때 준비·검증·조건 구성·조회·변경·결과 조립의 흐름이 드러나도록 작성한다. 실제로 존재하는 처리 단계에만 구간을 나누며, 서식을 위해 업무 로직이나 조회 횟수를 바꾸지 않는다.

사용자의 요청과 대상 프로젝트의 명시적 규칙을 먼저 확인한다. 변경 대상 메서드에 적용하며, 관련 없는 파일의 일괄 포맷이나 IDE 설정 변경을 추가하지 않는다.

## 역할별 구간과 주석

- 여러 역할이 이어지는 메서드는 **역할이 바뀌는 지점마다 빈 줄 한 줄로 구분하고, 각 구간의 시작에 짧은 한글 `//` 주석을 둔다.** 변수 준비, 조회 조건 구성, 조회 실행, 페이징, 후속 조회, 결과 조립 등이 실제 구분의 예다.
- 같은 목적의 선언·조건문은 한 구간에 모은다. 선언이라는 이유만으로 모든 변수를 메서드 맨 위로 옮기지 않고, 사용하는 구간 가까이에 둔다.
- 구간 주석은 무엇을 하려는지 설명한다. `// 현재 페이지의 첨부 조회`처럼 목적을 쓰고, 각 줄의 문법이나 변수명을 그대로 반복하지 않는다. 구간을 만들기 위한 불필요한 `{}` 블록은 추가하지 않는다.
- 짧은 한 가지 동작의 메서드까지 준비·실행·반환 구간으로 억지로 나누지 않는다. 단순 getter나 바로 위 코드로 자명한 한 줄 반환에 형식적인 주석을 붙이지 않는다.
- 이 `//` 주석은 메서드 내부의 처리 구간 설명이다. 호출 계약을 설명하는 JavaDoc을 대체하지 않으며, 모든 실행 줄에 주석을 붙이라는 뜻도 아니다.

## 호출과 표현식의 줄바꿈

- 여러 인자·중첩 생성자·체인 호출이 한 줄에 몰려 각 요소의 역할을 읽기 어려우면 여러 줄로 작성한다. 여러 줄로 펼친 호출은 여는 괄호 뒤에서 줄을 바꾸고, **인자 하나당 한 줄**, 닫는 괄호는 해당 호출의 들여쓰기에 맞는 별도 줄로 둔다.
- 긴 체인은 연산 경계마다 줄을 바꾸어 흐름을 읽을 수 있게 한다. 중간 연산과 마지막 실행·반환 연산을 한 줄에 다시 몰아넣지 않는다. 짧고 단순한 호출까지 무조건 여러 줄로 늘리지는 않는다.
- 여러 줄 호출 안의 삼항식이나 긴 조건식은 조건과 선택값이 구별되도록 펼친다. 예를 들어 `PageImpl` 생성자의 기본 건수 선택은 다음처럼 작성한다. 짧고 명확한 모든 삼항식에 이 모양을 강제하지는 않는다.

```java
final Page<ReservationRow> page = new PageImpl<>(
    parents,
    pageable,
    count == null
        ? 0
        : count
);
```

- 들여쓰기 폭과 import 정렬은 대상 프로젝트의 명시적 설정을 따른다. 수동 줄바꿈이 IDE에서 유지되는지는 실제 포매터 설정에 달려 있으므로, 이 규칙을 추가한 것만으로 IDE 설정도 변경됐다고 보지 않는다.

## 지역변수의 유지와 축소

- **선언 직후 반환에 전달할 뿐이고 이름이 의미를 더하지 않는 임시 변수는 만들지 않는다.** 아래처럼 바로 반환해도 처리 단계·평가 순서가 명확하면 직접 반환한다.

```java
return new ReservationPageRows(page, files);
```

- `final ReservationPageRows result = new ReservationPageRows(page, files); return result;`처럼 이름만 추가하는 패턴을 기본으로 사용하지 않는다.
- 사용 횟수만으로 판단하지 않는다. `parents`, `parentIds`, `count`, `page`, `files`처럼 조회 대상·결과·페이징 단계를 설명하거나 긴 표현식을 읽기 쉽게 나누는 변수는 한 번만 참조해도 유지할 수 있다.
- 후속 조건 검사, 재사용, 로깅, 결과 조립에 필요한 값은 지역변수로 둔다. 변수를 줄이려고 조회 실행을 생성자 인자에 중첩하거나 동일한 조회를 반복하지 않는다.
- 인라인할 때는 기존 호출 횟수·순서·예외 발생 시점과 조기 반환을 보존한다. 이 조건을 지키기 어려우면 의미 있는 이름을 가진 변수를 유지한다.

## 결과 확인

- 여러 역할이 있는 메서드에서 각 구간의 목적과 경계가 주석·빈 줄로 보이는지 확인한다.
- 긴 호출의 인자·체인이 분리됐는지, 지역변수를 없애면서 더 긴 중첩식이나 중복 호출을 만들지 않았는지 확인한다.
- 서식만 바꿨다면 기존 조건·인자 순서·반환값·실행 순서가 유지됐는지 변경 내용을 비교한다. 동작까지 바뀐 경우에는 해당 변경에 필요한 검증을 별도로 수행한다.
