# 스킬의 한글 이름

> 유지보수용 양식이다. `skills/<카테고리>/<스킬명>/SKILL.md`로 복사한 뒤 식별 정보와 본문을 실제 지침으로 바꾸고 이 안내를 지운다. 필요 없는 절은 삭제한다. [생성·유지보수 가이드](../MAINTENANCE.md)의 독립 사용 원칙에 따라 작성한다.

## 목적과 범위

- 이 스킬로 완성할 결과물을 설명한다.
- 원본 프로젝트나 작성자 이력을 언급하는 대신 어떤 입력과 작업에 적용할지 명시한다.
- 비슷해 보이지만 이 스킬을 적용하면 안 되는 작업이 있다면 구분한다.

## 작업 절차

1. 먼저 확인할 입력과 프로젝트 규칙을 적는다. 필수 정보가 없을 때의 처리도 필요한 경우에만 적는다.
2. 결과물을 만드는 데 필요한 핵심 절차와 판단 기준, 그 선택이 필요한 이유를 적는다.
3. 정확성을 위해 지켜야 할 고유 제약을 적는다. 일반적인 조언을 반복하지 않는다.

## 예시와 예외

- 판단이 어려운 조건에만 예시와 예외를 제공한다. 예시는 필요한 입력과 결과를 함께 제시해 외부 코드를 찾지 않아도 이해할 수 있게 한다.
- 조사한 프로젝트·계정·커밋을 예시의 근거로 나열하지 않는다. 설명에 불필요한 실제 식별자는 가상 입력으로 바꾼다.

## 필요한 자료와 도구

- 상세 자료는 `references/`, 실행 도구는 `scripts/`, 산출물용 자산은 `assets/`에 포함하고 상대경로로 연결한다. 실제로 필요한 폴더만 만든다.
- 자료를 읽을 조건과 도구의 입력·실행 환경을 적는다. 원본 프로젝트·특정 계정·과거 대화·외부 URL을 필수 지침 대신 참조하게 하지 않는다.
- 다른 스킬의 자료가 필요하면 인벤토리 내부 상대경로와 함께 배포할 범위를 명시한다.

## 결과물과 확인

- 결과물의 위치나 형식은 필요한 경우에만 지정한다. 사용자의 명시적 요청을 우선한다.
- 실제 완료 여부를 확인할 기준을 적는다.
- 현재 배포 파일과 작업 입력만 받은 사람이 제작 이력을 몰라도 이해·적용·유지보수할 수 있는지 확인한다.
