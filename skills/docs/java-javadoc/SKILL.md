# JavaDoc 작성

요청받은 Java 요소의 역할과 사용 계약을 소스에 맞게 한글 JavaDoc으로 설명한다. 일반 작성 지침과 함께 `eci-my247-api`의 이상수 작성 이력에서 확인한 enum 문서화 서식을 보존한다. 대상 프로젝트의 문서 규약과 현재 구현을 먼저 확인한다.

## 작업 범위

- 사용자가 지정한 파일·타입·메서드를 대상으로 한다. 단순 코드 수정 요청에 모든 클래스의 JavaDoc 작성을 추가하지 않는다.
- 별도 지정이 없으면 설명 문장은 한글로 쓰고 코드 식별자와 태그는 원래 표기를 유지한다.
- 주석 작성이 목적이면 메서드 서명이나 실행 로직을 변경하지 않는다. 설명과 구현이 다르면 확인된 차이를 알리고, 구현 변경은 요청 범위에 맞춰 판단한다.

## 작업 절차

1. 대상 소스와 인접한 JavaDoc, 프로젝트의 문서화 규칙을 확인한다.
2. 메서드 서명·구현·관련 호출부·테스트 중 설명에 필요한 근거를 읽는다. 선언만 보고 null 허용, 예외, 트랜잭션, 동시성 보장을 추측하지 않는다.
3. 유형별 주석을 작성할 때 [유형·레이어별 기준](references/type-and-layer-guidance.md)의 해당 절을 읽는다. Controller·Service 등 레이어가 관련될 때만 레이어별 절도 확인한다.
4. 첫 문장에 역할이나 결과를 요약한다. 이름을 되풀이하기보다 호출자가 알아야 할 전제·조건·부작용을 설명한다.
5. 아래 태그 기준을 적용하고 변경한 주석을 실제 코드와 다시 대조한다.

## 본문과 태그 기준

- 코드만으로 자명한 getter/setter나 내부 처리의 줄별 설명을 늘리지 않는다. 단위·값의 의미·선행 조건처럼 사용에 영향을 주는 정보를 적는다.
- `@param`: 매개변수명과 일치시킨다. 이름을 번역하는 데 그치지 않고 값의 의미, 확인된 허용 범위나 null 처리 등을 설명한다. 타입 매개변수는 `@param <T>` 형식이다.
- `@return`: 반환값의 의미와 확인된 빈 값·null 조건을 설명한다. 생성자와 `void` 메서드에는 작성하지 않는다.
- `@throws`: 실제로 발생하고 호출자가 알아야 할 예외와 발생 조건을 설명한다. 발생할 수 있다는 추측만으로 예외 목록을 늘리지 않는다.
- `{@link Type#method()}`: 실제로 존재하고 독자의 이해에 필요한 타입·메서드를 연결한다. `{@code ...}`는 식별자와 짧은 코드 표기에 사용한다.
- 재정의 메서드는 상위 계약과 달라지는 설명만 보완한다. 기존 규약에 맞으면 `{@inheritDoc}`을 사용할 수 있지만 원문 확인 없이 쓰지 않는다.
- `@author`, `@since`, `@version`은 프로젝트에서 요구하고 실제 값을 아는 경우에만 사용한다. 작성자나 버전을 만들지 않는다.

## enum의 별도 문서화

- enum을 문서화할 때는 타입 JavaDoc의 한글 개념 설명과 `{@link #상수}` 목록, 각 상수의 한글 설명을 함께 두는 서식을 사용한다. 기존 프로젝트가 다른 서식을 정했다면 그 규약을 우선한다.
- 상수 이름만으로 알기 어려운 업무상 의미와 적용 조건을 적는다. 확인되지 않은 DB 저장값이나 상태 전이를 추가하지 않는다.
- 공개 API의 enum이며 API 문서화도 요청된 경우에는 기존 Swagger `@Schema`에 같은 의미를 병기한다. JavaDoc만 요청받았다면 Swagger 어노테이션이나 의존성을 추가·수정하지 않는다.
- 실제 작성 시 [enum 서식과 출처](references/type-and-layer-guidance.md#enum-문서화-서식)를 읽는다. API 전체 명세도 함께 작업할 때만 `api-documentation`을 함께 적용한다.

## 결과물과 확인

- 파일 수정 요청이면 해당 소스의 JavaDoc을 수정한다. 예시 요청이면 복사할 수 있는 주석을 제공한다.
- 매개변수명·반환형·예외 조건·참조 링크가 실제 선언과 맞는지 확인한다. JavaDoc 안에서 HTML로 해석될 수 있는 코드는 `{@code ...}` 등으로 표시한다.
- 프로젝트에 JavaDoc 검사 절차가 있고 변경 범위상 필요하면 실행한다. 주석만 바꾼 작업에 관련 없는 전체 테스트를 일괄 실행하지 않는다.
- 결과 보고에는 변경한 대상과 확인 방법을 적는다. 문서 생성이나 실행 검증을 하지 않았다면 했다고 표현하지 않는다.
